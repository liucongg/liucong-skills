# 研究与证据

## 从问题而非关键词出发
先确认究竟是解释真实器物、系统机制，还是已有资料汇编。真实器物写明型号/代际/版本与范围；通用原理注明代表结构，不能杂糅单锅炉与双锅炉、不同车型的部件。

## 搜索顺序
1. 搜厂商手册、官方技术文档/仓库、标准机构；从这些文档找部件名、关键词和引用。
2. 用教材、论文、博物馆/大学等机构资料交叉检查原理。找不到独立资料时注明证据只有一条，不为了凑数量放无用链接。
3. 中文术语通过实际中文技术材料核对。中文搜索工具不可用时普通搜索引擎替代，不以翻译猜专业名词。
4. X/作品集只搜画法、讲法和读者反馈；具体帖子实际回读，不把搜索摘要当正文，不声称做过未执行的图片理解。

## source 与 claim 记录
来源示例：
```json
{"id":"S01","title":"来源的真实标题","url":"https://example.org/manual","kind":"official","verified":true,"retrieved_on":"YYYY-MM-DD","excerpt":"来自实际回读的摘录","license":"reference-only"}
```
`verified` 表示 Agent 确实回读了摘录对应内容，不等于所有结论自动正确。候选链接设 false，不可用于核心结论。日期用当前时钟工具，不猜当前日期。

结论示例：
```json
{"id":"C01","text":"这条要解释的具体机制","source_ids":["S01"],"status":"verified","critical":true}
```
`status` 只有 verified/assumption/unverified。assumption 只能用于已在书中明说的演示假设，不可作为真实产品参数。核心真实结构声明必须 verified；数学演示的假设可标 assumption 并带 calculation/test evidence。系统验证脚本检查引用完整性，不能证明摘录真伪，Agent仍须回读。

## 外部图像
图片同时记录页面URL、原图URL、作者、许可、使用方式；完整流程见 `image-workflow.md`。不能只存下载文件名。正式图可为SVG、已有授权图片、生成图片或混合图，由读者问题与证据需求决定。来源图片若只有参考权，留在研究目录，不进入再发行包。描摹改色不自动变成原创；生图也不是事实来源。照片用于辨认器物，原理图用于解释路径，各有任务。

## 数据与边界
表格/数字的单位、版本、工况同时记录。先用脚本算，再画对应数据；图里数值不能与正文不同。保留一个具体的反例或边界，防止读者把类比套到不适用场景。若某条资料会导致危险维修或制造误用，调整本书范围为原理科普。

## 证据门槛
至少一个直接支撑核心结论、实际回读的官方/教材/机构来源；高风险、存在冲突或非官方结构应交叉核查。可以在book.json提高min_verified_sources，但不能用无用途链接凑数。来源数量不是可靠性的替代品。未知参数可以省略或明确待核对，不能用生图/模型补成看似精确的数值。
