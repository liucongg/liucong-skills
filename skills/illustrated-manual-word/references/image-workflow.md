# 图片不是一种工具：先决定它要承担什么

## 四种制作方式

| 读者问题 | 优先方法 | 能力边界 |
|---|---|---|
| 真实产品长什么样、接口在哪里 | 已有官方图/本人实拍；缺合适图时有证据地重绘 SVG | 生图不能补充未知机型、按钮、接口或内部结构 |
| 机构为什么动、线路怎么连、前后状态如何变化 | SVG/数据驱动矢量图 | 总览/剖面/步骤共享结构、部件、坐标和状态，不能各自凭空画 |
| 材质、人物手势、环境、组织形态、情境导入 | 已有照片或生成图片 | 原图能满足就不多生成；生成结果不是照片取证，也不是事实来源 |
| 在实物照片上指出部件/路径 | 已有图片 + 独立 SVG 标注层（hybrid） | 不悄悄改实物；原图、标注层、合成结果都留存 |
| 图像原生效果明显更优的解释插画 | 带证据与参考图生成/编辑，再做结构审查 | 只有结构和状态都验证后才可作 technical；没通过退回 SVG 或原图，不默认降级成事实 |

这是判断顺序，不是固定“所有机械都 SVG/所有封面都生图”。可用 `terminal` 运行 `python <skill>/scripts/media.py plan <project>/figure-brief.json` 得到初判；Agent 用真实资料、版面用途和工具能力作最终决定，逐图写入 `decision_reason`。不得为了证明调用生图而加入无用装饰图。

## 搜图与已有图

1. 优先找来源网页而不是直接收缩略图。普通网页用 `web_search` + `web_extract`；图片搜索用当前实际可用的 image search 工具。Hermes 的豆包图片搜索需先 `tool_describe` 加载 `mcp__mcp_server_askecho_search_infinity__web_search`，设置 `SearchType=image`；其他平台用其本地可用工具，不强绑 MCP。
2. 图片搜索只做候选发现。回到厂商/作者/博物馆/开放图库页面，核对原图、型号、版本、发布日期与说明；下载原尺寸，不能把搜索摘要当已验证。
3. 图片搜索不可用时改用来源网页的 `<img>` / PDF 图版；正文提取看不到图时，用常规浏览器或本地 PDF 页图。401/无效密钥只记录一次，不读密钥、不安装重复服务、不循环呼叫。
4. 用 `media.py fetch https://... --out <project>/research/file.png --allow-host exact.domain` 获取允许的公开 HTTPS 栅格图。工具限制20MB、公共地址、白名单主机和重定向，不下载远程 SVG 或运行网页脚本。命令中不放签名 URL、令牌或凭据。需授权/签名的私有图用已有安全文件工具，保存无密钥出处。
5. 每图记录 `source_page`、`source_url`、实际 `retrieved_on`、作者/机构、`rights`、`usage`、本地文件 SHA256、原始 SHA256（若有）、允许的改动。官方≠公共领域；注明出处≠获得转载许可。
6. `usage=reference-only` 的原图只留在研究目录，不嵌入最终书、不进入可再发行 Skill ZIP。有明确许可或用户给出使用权的图片才进入交付；没有许可也没有足够合理使用依据时选原创重绘/替代素材，并说明局限，不自动宣布已获许可。

## 生图与编辑

- 当前 Hermes 默认 `image_generate`，不由 Skill 写死模型或 API 秘钥；其他宿主使用其原生生图能力。缺工具/配额时如实说明，选已有图或SVG，不伪造生成结果。模型提供文字能力不意味着有生图能力。
- 提示词先写图片用途、可用素材、必须保真的对象/结构，再写镜头、材质与构图；每次只解决一个明确问题。真实对象编辑时传原图；多状态尽量基于同一母图/参考和结构表，不能独立生成不同产品。
- 区分“情境图”和“解释图”：情境图能帮助进入问题，但不能拿来证明阀门数量、管路、接口、尺寸、安全操作。配图旁标明 AI 情境插图；不称其为现场照片。
- 生成 technical 插图，必须在 `generation` 记录真实 prompt、provider/model（以工具返回为准）、时间、参考图 ID 和生成结果路径，保存结构对照。逐项检查部件、连接、动作、遮挡、箭头、数字、跨图一致性；图中的读数/文字优先由可编辑正文或SVG覆盖。
- 有错误时在当前授权范围内有针对性编辑，不扩大为新的画风/对象；仍无法保真时将该图拒收，并转SVG/已有图。不要把失败图偷偷改为已通过。
- 默认正文、步骤、警告、表格与图注留在 Word 原生文字；生图画面的长段正文不算可编辑。示意图短标签允许嵌入图片，长说明不能被栅格化。
- 通用协议不携带隐私/身份素材。涉及特定人物、角色、企业头像或客户材料时另遵守其权威参考与权限；不可套用他人画像。

## SVG与混合图

需要确定几何、状态、数量、连接或数据时先结构表，再SVG。参考 Anatomy 的 craft/完整案例/verify；图本身在1×解释问题，在4×能检查支撑、接口、切面、连线与细节收口。

SVG需自包含：保留 viewBox；禁脚本、动画、远程资源和 foreignObject。混合图先保留合法原图，再独立输出标注层；合成时对齐同一坐标系，不靠肉眼拖到差不多。透明背景合成到白纸，不直接RGB变黑；必要裁切写入 manifest，不拉伸比例。

## 图片清单与验收

`<project>/media.json` 采用 `templates/media.example.json` 的字段。每图有 id/path/method/role/purpose/decision_reason/alt_text/rights/sha256/width_mm。role 为 technical/context/reference。technical 绑定来源；generated 有实际 generation 记录。SVG另留 svg 文件路径。

用 `media.py check` 验证文件/hash/公开URL/尺寸与声明；用 `media.py contact` 做素材预览；必须实际打开并审查。technical 在最终宽度最低250ppi，照片/情境图最低150ppi，标签/细线则按真实可读性要求更高。PPI通过不保证结构或美术正确。

book.json 的 figure 用 method/role/asset_id 与 media.json 关联；schema_version=0.3强制校验。SVG图有svg与png；已有/生成/混合图只需兼容PNG和保留对应源文件，不伪造SVG套壳。Word正文仍可编辑，图内零件不承诺为Word独立图形对象。
